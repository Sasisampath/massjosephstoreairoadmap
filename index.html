The practical AI build guide · 01

Mass Joseph StoreTamil AI Voice Agent Roadmap

Build a Tamil-speaking grocery order assistant, from the first voice conversation to a dashboard with human approval.

8 stagesBeginner → intermediatePortfolio project · Educational prototype

Overview

What you will build

A Tamil-speaking AI assistant takes a grocery order, extracts the items and delivery preferences, and places a draft into a simple dashboard. The shop owner checks the address, stock and delivery time before accepting anything.

STEP 1Customer conversation
STEP 2ElevenLabs agent
STEP 3Verified post-call webhook
STEP 4Order extraction / Gemini (optional)
STEP 5Pending-order dashboard
STEP 6Human review

Important: Claude Code helps you build the app. It does not answer customer calls at runtime. ElevenLabs handles the voice interaction; Gemini is optional for normalizing transcripts.

Educational prototype. Fan-made demonstration inspired by a familiar Tamil shop meme. Not affiliated with a real Mass Joseph Store, ElevenLabs, Anthropic, or Google. No real customer calls, approvals or deliveries are implied. This guide uses fictional data.
01

Stage 1 · Planning

Plan the order flow

  • Define five sample products: Ponni rice (25 kg bag), toor dal (kg), palm oil (litre), wheat flour (kg), millets (kg).
  • Decide the minimum details: customer name, phone (if available and consented), product and quantity, full delivery address, preferred time, special notes.
  • Define statuses: DRAFT, NEEDS_DETAILS, AWAITING_MERCHANT_APPROVAL, CONFIRMED, READY_FOR_DELIVERY, COMPLETED.
  • Make a rule: the voice agent can request an order, never guarantee stock, final price or delivery.

Done when: You can describe the entire call and merchant review in one diagram.

02

Stage 2 · Voice

Create the Tamil agent in ElevenLabs

  • Open the ElevenLabs Agents platform and create a new agent.
  • Choose a suitable Tamil-capable voice and language configuration; test pronunciation of rice varieties and units.
  • Give it the instructions below; test in the browser first, without a paid phone number.
  • Request details one at a time; repeat the entire order back and ask for confirmation.
  • Treat an area name like “Velachery, Chennai” as incomplete until street, door/building and landmark (when needed) are provided.
  • Clearly introduce itself as an AI assistant.
ElevenLabs · Agent instructions
You are the Tamil-speaking AI ordering assistant for a fictional grocery-store portfolio demo inspired by Mass Joseph Store.
Speak friendly, clear everyday Tamil, not formal corporate Tamil.
Start: "Vanakkam! Mass Joseph Store-la irundhu AI udhaviyalar pesuren. Enna order venum, sollunga?"
Gather customer name, items, quantities/units, full delivery address, requested time and payment preference.
If the brand or rice variety is ambiguous, ask a question. Never invent it.
Confirm the final item list and quantities. Repeat the exact address and ask the caller to confirm it.
Never claim stock, price, payment or delivery is confirmed. Say the shop owner will check and confirm.
Do not collect card PINs, passwords, UPI PINs or OTPs.
If caller wants to end the conversation, politely end it; do not ask another question after goodbye.
If you cannot understand a detail, mark it unclear and ask the caller again.
This is a prototype demo, not a real business phone line.

Done when: A genuine test call captures rice, dal, oil, the requested time and a clearly confirmed address.

03

Stage 3 · Build

Build the dashboard with Claude Code

Use Claude Code to build a small Next.js + TypeScript dashboard with a sample order, list view, order detail, editable fields and an approval button. Start in demo mode with fictional orders. Store only what’s necessary. Do not expose secret keys in browser code.

Claude Code · Starter prompt
Build a mobile-first grocery order intake dashboard for an educational prototype named Mass Joseph Store AI Automation.
Tech: Next.js, TypeScript, Tailwind CSS; SQLite or a lightweight local demo store.
Screens: Today's Orders, Needs Details, Awaiting Approval, Order Detail, Merchant Review.
Fields: customer, line items (name, quantity, unit), address, requested time, payment preference, transcript excerpt, status.
Use seeded fictional data and a visible 'Prototype Demo' label.
Allow staff to correct items and addresses. Merchant approval must be explicit.
Never auto-confirm, dispatch, charge or message a customer. Keep demo mode separate from live integrations.
Provide safe API routes for receiving post-call data and show missing address fields as incomplete.
Build, run tests, and explain verified vs simulated behaviors. Do not commit, push or deploy.

Done when: A fake sample order appears, can be edited, and only changes to confirmed after explicit merchant approval.

04

Stage 4 · Integration

Move the conversation to the app

  • In ElevenLabs, configure a post-call webhook (or a secure server tool if you need an action during the call).
  • On your backend, verify the event signature using the raw request body and configured webhook secret, as specified in ElevenLabs docs.
  • De-duplicate repeated webhook deliveries using a stable event or conversation identifier.
  • Save the transcript and data-collection result as a draft. Never present it as a confirmed paid order.
  • If no webhook is connected yet, demonstrate with a labelled manual JSON import instead of claiming a live integration.

Done when: A completed test conversation creates one pending draft in the local dashboard, even if the webhook retries.

05

Stage 5 · Optional

Use Gemini only if it adds value

You can use ElevenLabs built-in data collection for structured fields without Gemini. If transcripts are messy or bilingual, add Gemini server-side using schema-constrained structured output to standardize item names and flag missing fields.

Example target JSON
{
  "customer_name": "Demo Customer",
  "items": [
    {
      "name": "Ponni rice",
      "quantity": 25,
      "unit": "kg"
    },

      "quantity": 2,

    },

    }
  ],
  "delivery_address": {
    "area": "Velachery, Chennai",
    "full_address": null
  },
  "requested_delivery_time": "Tomorrow 08:30 (not confirmed)",
  "payment_preference": "UPI",
  "missing_details": [
    "street and door/building number"
  ],
  "status": "NEEDS_DETAILS"
}
  • Validate all output on the server. Use proper date values and local time zone in a real app; the above is explanatory sample data, not an API contract.
  • Never let AI autonomously approve, charge, dispatch or claim completed delivery.

Done when: Missing address stays missing; the UI highlights what Anna must verify.

06

Stage 6 · Testing

Test before making claims

Test at least these cases:

  1. Straightforward order: Ponni rice 25 kg, toor dal 2 kg, palm oil 1 L.
  2. Ambiguous rice variety: agent asks which type.
  3. Incomplete address: marks order NEEDS_DETAILS.
  4. Delivery time preference: stays requested, never guaranteed.
  5. Goodbye: agent stops talking.
  6. Duplicate webhook: one order only.
  7. Payment preference UPI: never claims payment received.
  8. Merchant approval: requires explicit human action.

Record what worked and what is still mocked. Use fictional identities and addresses in public demo clips.

07

Stage 7 · Advanced · Optional

Optional real phone integration

Only after the browser demo and dashboard work, consider a real inbound number through Twilio/ElevenLabs or another officially supported telephony option. This requires appropriate accounts, permissions, local availability, call disclosure, privacy controls and paid services. Start with a test number, not a shop’s existing phone. Obtain authorization before any real customer handling.

08

Stage 8 · Portfolio

Package it as a portfolio case study

  • Problem: a busy kirana/rice-shop owner answers every delivery call.
  • Solution: Tamil voice order capture, pending-order dashboard and merchant approval.
  • Proof: real ElevenLabs test recording, a real running dashboard and integration test logs.
  • Limitations: clearly identify simulated UI, unverified delivery and any incomplete integrations.
  • Learning: handling Tamil names, rice varieties, quantities, addresses and human-in-the-loop approval.
